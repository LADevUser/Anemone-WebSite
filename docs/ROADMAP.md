# Anemone Website Roadmap

## Completed milestones

- Established Astro 6 static-site foundation
- Added GitHub Actions deployment to GitHub Pages
- Configured the `/Anemone-WebSite` production base path
- Added shared layout, header, footer, and responsive navigation
- Integrated assets from `public/branding/`
- Established the calm Nordic botanical visual foundation
- Added Journal and Projects Content Collections
- Added collection listings and static detail pages
- Added initial Swedish demo content
- Expanded the Anemone OS project presentation and summary metadata
- Updated the visible participation label from Delta to Bidra while retaining
  the existing `/delta/` route

## Current phase

The current phase is content foundation and preparation for a small internal
demo. The priority is clear, credible content and a reliable static experience,
not feature expansion.

## Near-term next steps

- Replace placeholder copy on Vision, Filosofi, and Bidra
- Review all demo copy for consistency, spelling, and tone
- Confirm project descriptions, statuses, audiences, and ordering
- Review external references in the Anemone OS article before public use
- Check desktop and mobile presentation across all routes
- Add essential social and SEO metadata using existing branding assets
- Review accessibility with keyboard navigation and automated checks
- Merge the content-foundation branch into `main` when demo content is approved

## Later possible improvements

These are options, not commitments:

- Add more journal and project entries through existing collections
- Introduce reusable content components only when repeated needs are clear
- Add an RSS feed for Journal
- Add sitemap and richer Open Graph metadata
- Add a custom domain
- Add basic image optimization where it provides measurable benefit
- Revisit typography assets if brand requirements justify local font files
- Add lightweight automated checks for formatting, links, or accessibility

## Explicitly deferred

- CMS or non-Git editorial interface
- Database or server-side application layer
- Search
- Tags and categories
- Pagination
- User accounts or authentication
- Analytics and tracking
- Comments or community features
- Tailwind or another UI framework
- React, Vue, or other client-side frameworks
- Animation libraries
- E-commerce, payments, or forms backed by external services
- Renaming the `/delta/` route to `/bidra/`
- Large-scale design-system abstraction

Deferred items should only be reconsidered when a concrete user or operational
need exists.
